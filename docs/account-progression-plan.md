# 계정 진행 계획

현재 결론: `12턴 런 세이브`와 별도로 `계정 메타 세이브`를 만들고, 12턴 종료 시 `계정 레벨`, `완주 횟수`, `최고 순자산`, `영구 해금`만 누적 저장한다. 이 레벨은 현재 구현된 `외모 레벨`과 분리해서 반드시 `계정 레벨` 또는 `회차 레벨`로 표기한다.

## 목적

- `12턴 종료 = 게임 끝`이 아니라 `다음 회차 시작점 갱신`으로 읽히게 만든다.
- 브라우저를 닫았다 다시 열어도 플레이어의 장기 진행 상태가 남게 만든다.
- 현재 `localStorage` 기반 런 세이브 구조를 크게 깨지 않고 메타 진행을 얹는다.
- 나중에 Firebase 같은 서버 계정으로 확장할 수 있도록 최소 구조를 먼저 고정한다.

## 현재 관련 동작

- 런 세이브:
  - `js/logic.js`의 `SAVE_STATE_KEY = "mammon-city-save-v1"`를 사용한다.
  - 저장/복구는 현재 한 회차 플레이 상태만 대상으로 한다.
- 2026-06 게스트 전용 배포:
  - 공개 플레이 링크는 Google/이메일 로그인 UI를 숨기고 게스트 시작만 노출한다.
  - 게스트 시작은 닉네임이 비어 있으면 `게스트`로 자동 시작한다.
  - Firebase 초기화는 기본 배포에서 끄고, 랭킹/커뮤니티 쓰기는 오프라인 fallback 기준으로만 동작한다.
- 새 게임 시작:
  - `startGame()`가 새 상태를 만들고 수저 시작 패키지를 적용한다.
- 12턴 종료:
  - `finishRun()`가 `endingSummary`를 만들고 랭킹 제출까지 이어진다.
- 타이틀 복귀:
  - `restartToTitle()`는 현재 런 세이브를 지우고 처음 화면으로 돌아간다.
- 메타 뼈대:
  - `js/systems/progression/meta-state-service.js`에는 `progression / unlocks / social / risk / business` 기본 구조가 이미 있다.
- 레벨 충돌 위험:
  - `js/systems/presentation/presentation-service.js`에는 이미 외모도 기준 `getPlayerAppearanceLevel()`이 있다.
  - 따라서 새 메타 레벨을 `level` 하나로 넣으면 의미가 섞인다.

## 이번 계획의 핵심 원칙

1. `런 세이브`와 `계정 메타 세이브`를 분리한다.
2. 메타 저장은 `12턴 완주` 시점에만 갱신한다.
3. 중간 저장을 불러와도 계정 레벨이 중복 상승하지 않게 막는다.
4. 첫 버전은 `localStorage`만 사용한다.
5. 현재 플레이 밸런스를 무너뜨리지 않도록 `시작 보너스`는 작게 둔다.

## 권장 플레이 흐름

1. 타이틀 진입 시 계정 메타 세이브를 먼저 읽는다.
2. 메타 세이브가 있으면 타이틀에 `계정 레벨 / 완주 횟수 / 최고 순자산`을 보여준다.
3. 새 게임을 시작하면 계정 메타의 영구 보너스를 현재 회차 시작 상태에 적용한다.
4. 플레이 도중에는 기존 런 세이브만 계속 갱신한다.
5. 12턴이 끝나 `finishRun()`에 도달하면 `endingSummary`를 기준으로 계정 메타를 1회 갱신한다.
6. 타이틀로 돌아가도 메타 세이브는 유지되고, 런 세이브만 지운다.
7. 다음 회차는 갱신된 계정 레벨과 해금 상태를 반영해 시작한다.

## 현재 메인 화면 기준 추천 배치

현재 메인 화면에는 이미 아래 요소가 있다.

- `Google로 로그인`
- `이메일로 로그인`
- `게스트로 시작하기`
- `닉네임` 입력
- `이어하기`
- `시작하기 / 새로하기`

이 구조면 새 계정 진행 UI를 크게 뜯지 않고도 자연스럽게 얹을 수 있다.

### 권장 배치 순서

1. 로그인/게스트 선택 영역 유지
2. 그 아래에 `계정 메타 요약 카드` 추가
3. 그 아래에 `닉네임` 입력
4. 맨 아래 액션 버튼은 `이어하기 / 새 회차 시작`으로 유지

### 계정 메타 요약 카드 예시

- `계정 3레벨`
- `완주 3회`
- `최고 순자산 12,500,000원`
- `최근 기록 A / 상류층 진입`

요약 카드는 큰 패널보다 얇은 칩 3~4개 또는 한 줄 카드가 더 어울린다. 현재 메인 화면은 CTA 밀도가 높아서, 메타 정보까지 큰 박스로 넣으면 답답해질 가능성이 크다.

### 버튼 의미 분리

- `이어하기`
  - 현재 회차 런 세이브가 있을 때만 노출
  - 기존 `mammon-city-save-v1`를 복구
- `새 회차 시작`
  - 현재 회차를 새로 시작
  - 계정 메타 보너스를 적용한 새 런 생성
- `게스트로 시작하기`
  - 로그인 없이 진행
  - 첫 버전에서는 이 경우에도 같은 브라우저 안에서는 메타 진행을 남길 수 있다
  - 단, 문구로 `이 브라우저에서만 유지됨`을 분명히 보여주는 편이 좋다

### 닉네임 입력 동작

- 로그인 상태면 마지막 닉네임을 자동 채움
- 게스트 상태여도 마지막 로컬 닉네임을 자동 채울 수 있다
- 닉네임은 `계정 식별자`가 아니라 `표시 이름`으로만 취급한다

### 로그인 상태별 노출 규칙

- 비로그인 + 메타 없음
  - 로그인 버튼 강조
  - 메타 요약 카드는 숨김 또는 `처음 시작` 문구만 노출
- 비로그인 + 로컬 메타 있음
  - `로컬 진행 유지 중` 보조 문구
  - `계정 2레벨 / 완주 2회` 정도는 노출 가능
- 로그인 + 메타 있음
  - 메타 요약 카드 전체 노출
  - 필요 시 `클라우드 동기화됨` 같은 작은 상태 문구 추가

### 현재 화면에 맞는 최소 문구 수정안

- `시작하기` -> `새 회차 시작`
- `게스트로 시작하기` 아래 보조 문구 추가
  - `게스트 진행은 현재 브라우저에만 저장됩니다.`
- 개인정보 문구와 별개로 메타 저장 안내 1줄 추가 가능
  - `완주 기록과 최고 순자산은 계정 진행 정보로 유지됩니다.`

## V1 권장 규칙

### 계정 레벨 규칙

- `12턴 완주 1회 = 계정 레벨 +1`
- 실패 런이나 중도 종료 런에는 레벨을 주지 않는다.
- 첫 버전은 단순하게 `완주 횟수 = 계정 레벨`로 둬도 된다.

### V1 시작 보너스

- `startingCashBonus = min(accountLevel * 10000, 100000)`
- `startHappinessBonus = min(accountLevel * 2, 10)`
- `autofillPlayerName = 마지막 플레이어 이름 유지`

위 3개부터 시작하면 구현은 단순하고, 초반 밸런스가 한 번에 무너지지 않는다.

### V1에서 보류할 것

- 집 구매 후 다음 회차 시작지 변경
- 직업군별 영구 특전
- 범죄 루트 전용 메타 시작 조건
- 서버 로그인과 다중 기기 동기화

위 항목은 `docs/design/progression.md`의 더 큰 설계 범위로 남겨둔다.

## 현재 코드 기준 추천 접점

### 1. 메타 세이브 헬퍼 추가

- 후보 위치:
  - `js/logic.js`의 런 세이브 헬퍼 근처
- 필요한 함수:
  - `createDefaultAccountMetaState()`
  - `loadAccountMetaState()`
  - `persistAccountMetaState()`
  - `clearAccountMetaState()`
  - `applyAccountMetaBonusesToNewRun()`
  - `commitAccountProgressFromEndingSummary()`

### 2. 타이틀 진입 시 메타 읽기

- `DOMContentLoaded` 시점에 런 세이브와 함께 메타 세이브도 읽는다.
- 시작 화면 UI에는 최소한 아래 3개를 보여준다.
  - 계정 레벨
  - 완주 횟수
  - 최고 순자산

### 3. 새 게임 시작 시 메타 적용

- `startGame()` 안에서 `createInitialState()` 후, 수저 패키지 적용 전후 순서를 정해 메타 보너스를 넣는다.
- 권장 순서:
  1. `createInitialState()`
  2. 수저 시작 패키지 적용
  3. 계정 메타 시작 보너스 적용
  4. 인트로/잡 오퍼 준비

### 4. 12턴 종료 시 메타 커밋

- `finishRun()`에서 `endingSummary`가 준비된 직후 메타 커밋을 호출한다.
- 커밋에는 아래 값이 필요하다.
  - 플레이어 이름
  - 최종 순자산
  - 최종 행복도
  - 최종 랭크
  - 출신 수저
  - 완료 시각

### 5. 타이틀 복귀 시 메타 유지

- `restartToTitle()`는 기존처럼 런 세이브만 지운다.
- 메타 세이브는 유지해서 다음 회차에 다시 읽게 만든다.

## 중복 반영 방지 규칙

- `finishRun()`는 엔딩/랭킹 진입 중 한 번만 메타를 갱신해야 한다.
- 저장 후 `ending` 세이브를 다시 불러와도 계정 레벨이 또 오르면 안 된다.
- 권장 방법:
  - 회차마다 `runId`를 하나 만든다.
  - 메타 세이브에 `lastCommittedRunId`를 기록한다.
  - 같은 `runId`는 다시 커밋하지 않는다.

## UI 권장 문구

- `계정 3레벨`
- `완주 3회`
- `최고 순자산 12,500,000원`
- `이번 완주로 계정 레벨이 올랐다`

`1LV`, `2LV` 같은 표기는 외모도 UI와 겹쳐 보일 수 있으니 타이틀/메타 화면에서는 `계정 3레벨`처럼 한글 레이블을 붙이는 편이 안전하다.

## 리스크

- `레벨`이라는 단어가 외모 레벨과 충돌할 수 있다.
- `finishRun()` 중복 호출이나 저장 복구 경로 때문에 계정 레벨이 두 번 오를 수 있다.
- 시작 보너스를 크게 주면 수저 시작 패키지 의미가 급격히 약해질 수 있다.
- 브라우저 저장만 쓰는 동안에는 기기 변경 시 계정이 유지되지 않는다.
- 랭킹용 익명 식별키와 계정 메타 식별키를 섣불리 합치면 책임이 섞일 수 있다.

## 완료 조건

- `12턴 완주 -> 타이틀 복귀 -> 새 게임 시작` 흐름에서 계정 메타가 유지된다.
- 타이틀에서 계정 레벨과 최고 기록을 확인할 수 있다.
- 새 회차 시작 시 작은 메타 보너스가 정상 반영된다.
- 엔딩 세이브를 다시 불러와도 레벨 중복 상승이 없다.
- 기존 런 세이브/이어하기 흐름은 깨지지 않는다.
